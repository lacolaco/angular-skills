# Angular 20 → 21

Generated from angular/angular @ 28d59e8d6357b6f5015657f06ecd7b543f00aba0

## During the update

- **[Basic]** In the application's project directory, run `ng update @angular/core@21 @angular/cli@21` to update your application to Angular v21.
  `21.0.0_ng_update`

- **[Basic] [Angular Material only]** Run `ng update @angular/material@21`.
  `update @angular/material`

- **[Advanced]** When using signal inputs with Angular custom elements, update property access to be direct (`elementRef.newInput`) instead of a function call (`elementRef.newInput()`) to align with the behavior of decorator-based inputs.
  `21.0.0-update-signal-input-access-in-custom-elements`

- **[Advanced]** If using `provideZoneChangeDetection` without the ZoneJS polyfill, note that the internal scheduler is now always enabled. Review your app's timing as this may alter behavior that previously relied on the disabled scheduler.
  `21.0.0-zone-scheduler-behavior-change`

- **[Basic]** Zone-based applications should add `provideZoneChangeDetection()` to your application's root providers. For standalone apps, add it to the `bootstrapApplication` call. For NgModule-based apps, add it to your root `AppModule`'s `providers` array. An automated migration should handle this.
  `21.0.0-provide-zone-change-detection-required`

- **[Advanced]** Remove the 'interpolation' property from your @Component decorators. Angular now only supports the default '{{' and '}}' interpolation markers.
  `21.0.0-remove-interpolation-option`

- **[Medium]** Remove the 'moduleId' property from your @Component decorators. This property was used for resolving relative URLs for templates and styles, a functionality now handled by modern build tools.
  `21.0.0-remove-moduleid-property`

- **[Medium]** The `ngComponentOutletContent` input has been strictly typed from `any[][]` to `Node[][]`. Update the value you pass to this input to match the new `Node[][] | undefined` type.
  `21.0.0-ng-component-outlet-content-type-change`

- **[Basic]** Host binding type checking is now enabled by default and may surface new build errors. Resolve any new type errors or set `typeCheckHostBindings: false` in your `tsconfig.json`'s `angularCompilerOptions`.
  `21.0.0-stricter-host-binding-type-checking`

- **[Basic]** Update your project's TypeScript version to 5.9 or later. The `ng update` command will typically handle this automatically.
  `21.0.0-typescript-5.9-required`

- **[Medium]** The `ApplicationConfig` export from `@angular/platform-browser` has been removed. Update your imports to use `ApplicationConfig` from `@angular/core` instead.
  `21.0.0-remove-application-config-from-platform-browser`

- **[Advanced]** The `ignoreChangesOutsideZone` option for configuring ZoneJS is no longer available. Remove this option from your ZoneJS configuration in your polyfills file.
  `21.0.0-remove-ignore-changes-outside-zone-option`

- **[Medium]** Update tests using `provideZoneChangeDetection` as TestBed now rethrows errors. Fix the underlying issues in your tests or, as a last resort, configure TestBed with `rethrowApplicationErrors: false` to disable this behavior.
  `21.0.0-testbed-rethrows-errors-with-provideZoneChangeDetection`

- **[Medium]** Update tests that rely on router navigation timing. Navigations may now take additional microtasks to complete. Ensure navigations are fully completed before making assertions, for example by using `fakeAsync` with `flush` or waiting for promises/observables to resolve.
  `21.0.0-router-navigation-timing-changed`

- **[Medium]** Tests using `TestBed` might be affected by the new fake `PlatformLocation`. If your tests fail, provide the old `MockPlatformLocation` from `@angular/common/testing` via `{provide: PlatformLocation, useClass: MockPlatformLocation}` in your `TestBed` configuration.
  `21.0.0-test-bed-provides-fake-platform-location`

- **[Advanced]** The `UpgradeAdapter` has been removed. Update your hybrid Angular/AngularJS application to use the static APIs from the `@angular/upgrade/static` package instead.
  `21.0.0-remove-upgrade-adapter`

- **[Medium]** The new standalone `formArray` directive might conflict with existing custom directives or inputs. Rename any custom directives named `FormArray` or inputs named `formArray` on elements that also use reactive forms to resolve the conflict.
  `21.0.0-form-array-directive-conflict`

- **[Advanced]** The deprecated `NgModuleFactory` has been removed. Update any code that uses `NgModuleFactory` to use `NgModule` directly, which is common in dynamic component loading scenarios.
  `21.0.0-ngmodulefactory-removed`

- **[Advanced]** The `emitDeclarationOnly` TypeScript compiler option is not supported. Please disable it in your `tsconfig.json` file to allow the Angular compiler to function correctly.
  `21.0.0-emit-declaration-only-not-supported`

- **[Medium]** The `lastSuccessfulNavigation` property on the Router has been converted to a signal. To get its value, you now need to invoke it as a function: `router.lastSuccessfulNavigation()`.
  `21.0.0-lastsuccessfulnavigation-is-a-signal`

- **[Medium]** Starting `@angular/ssr` 21.1.5, if your application uses SSR with `CommonEngine`, set the `allowedHosts` option in your `server.ts` (for example, `new CommonEngine({allowedHosts: ['localhost', '*.yourdomain.com']})`). Without it, SSR silently falls back to client-side rendering. This requirement comes from security advisory [GHSA-x288-3778-4hhx](https://github.com/angular/angular-cli/security/advisories/GHSA-x288-3778-4hhx) (also backported to 20.3.17 and 19.2.21).
  `21.0.0-configure-commonengine-allowed-hosts`
